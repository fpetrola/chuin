## Grows

- tui-api
  - `com.fpetrola.tui.InputLine#text(): String`
  - `com.fpetrola.tui.ListBox#selected(): Optional<String>`

## Need

ReadingWhatWasEnteredTest needs the code of an application, here a button's listener, to read what the person entered: the text typed into an input line and the item selected in a list box, to answer "Hola Ana, elegiste Verde". Today views hand their state only to a ViewVisitor, which is right for the desktop and the painter but leaves an application nothing to ask.

## Considered

ViewVisitor#inputLine(InputLine, String, int, Consumer<Character>, Runnable) and ViewVisitor#listBox(ListBox, List<String>, int, int, int, Runnable, Runnable) already hand over the text and the selection, but an application would have to write a whole visitor and accept it on the view to read one value; a getter on the view it already holds says the same in one call.
